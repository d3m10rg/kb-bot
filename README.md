# Telegram-бот для модерации группы

Бот проверяет новых участников математической капчей, удаляет стикеры из
запрещённых наборов и выдаёт мут после третьего употребления слова «балл» в
любой падежной форме.

Дополнительно бот:

- удаляет игровые эмодзи 🎰 🎲 🎯 🎳 🏀 ⚽ через 60 секунд после отправки;
- выдаёт мут на 5 минут за максимальный результат: 777 у 🎰 (64), 6 у
  🎲/🎯/🎳, 5 у 🏀/⚽; пересланные игры только удаляются;
- позволяет администраторам выдавать `/warn @username` или `/warn` ответом
  на сообщение участника; начиная с третьего предупреждения выдаёт мут на сутки;
- удаляет свои сообщения через 60 секунд, включая предупреждения и капчу.

Речь об игровых сообщениях Telegram с полем `dice`, а не об обычном тексте
с эмодзи или стикерах из произвольных наборов. Значения игр описаны в
[документации Telegram](https://core.telegram.org/api/dice).

Ответ на команду: `Пользователю @username дано предупреждение. Количество предупреждений: N`.
Счётчик `/warn` сохраняется отдельно для каждого участника каждого чата и
не сбрасывается после мута. Последующие `/warn` при N ≥ 3 снова дают сутки
мута. Предупреждения за слово «балл» по-прежнему имеют отдельный счётчик и
длительность `MUTE_MINUTES`. Более долгий действующий мут не сокращается.

Для поиска по `@username` бот запоминает участников по новым сообщениям и
изменениям членства. Если бот ещё не видел участника или тот сменил username,
используйте `/warn` ответом на его сообщение. Пользователя без username также
можно предупредить ответом. Перед предупреждением бот проверяет текущий
профиль и членство. Администраторов, владельца и ботов он не мутит.

## Запуск

1. Скопируйте конфигурацию и заполните её:

   ```bash
   cp .env.example .env
   ```

2. Соберите и запустите контейнер:

   ```bash
   docker compose up --build -d
   ```

3. Добавьте бота в **супергруппу** как администратора. Ему нужны права:
   удалять сообщения, блокировать пользователей и ограничивать участников.
   В BotFather отключите Privacy Mode, чтобы бот получал обычные сообщения
   группы и мог применять политику слова «баллы».

Логи:

```bash
docker compose logs -f bot
```

Остановка:

```bash
docker compose down
```

SQLite хранится в Docker volume `bot-data`, поэтому попытки, предупреждения,
известные username, незавершённые капчи и очередь удаления переживают перезапуск.
Новые таблицы создаются автоматически в существующей базе. Просроченные
удаления выполняются после запуска; при работе очередь проверяется раз в секунду.
`.env` намеренно исключён и из git, и из Docker
image; Compose передаёт его значения контейнеру через `env_file`.

## Настройка

- `BOT_TOKEN` — токен от BotFather.
- `FORBIDDEN_STICKER_PACKS` — короткие имена наборов через запятую. Это именно
  `set_name`, обычно он виден в конце ссылки `t.me/addstickers/<set_name>`.
- `MUTE_MINUTES` — длительность мута после третьего нарушения политики слова «балл».
- `CAPTCHA_TIMEOUT_SECONDS` — время ответа на капчу; по умолчанию 60 секунд.
  Значения выше 60 ограничиваются минутой, чтобы время ответа не превышало
  срок жизни сообщения с кнопками.
- `WARNING_TEXT_1`, `WARNING_TEXT_2`, `WARNING_TEXT_3` — многострочные тексты
  трёх предупреждений.
- `DATABASE_PATH` — путь к SQLite; в Compose уже настроен постоянный volume.

Администраторы и владелец чата полностью исключены из политики слова «баллы».
После неправильного ответа или тайм-аута бот банит и сразу разбанивает
пользователя: тот удаляется из чата, но может зайти снова.
